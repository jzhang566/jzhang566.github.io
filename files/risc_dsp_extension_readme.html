RV32 DSP Extension — RTL (v1, Q1.15)

SystemVerilog RTL for the Q1.15 fixed-point DSP extension, built and verified bottom-up. Target: Zynq-7020, paired with a CV32E40X host over CV-X-IF v1.0.0. DSP48 inference (no manual primitive instantiation).

Modules and status

Step Module What it is Testbench Status
1 q15_alu Single-lane saturating Q1.15 add/sub/mul tb_q15_alu PASS (6433 vec)
2 q15_valu 8-lane packed vector ALU (vsadd/vssub/vsmul) tb_q15_valu PASS (4560 vec)
3 vrf 16×128 register file, 2R1W, write-first tb_vrf PASS (10032 chk)
4 q15_mac 64-bit accumulators, vmacc/vmsac, vextract tb_q15_mac PASS (840 chk)
5 q15_cmul Packed complex multiply (vcmul/.conj) tb_q15_cmul PASS (8642 vec)
6 dsp_cvxif CV-X-IF adapter for scalar packed ops tb_dsp_cvxif PASS (309 chk)

Support: cvxif_pkg (CV-X-IF v1.0.0 types), dsp_decode (scalar op decoder).
Golden models: q15_ref.py, q15_valu_ref.py, mac_ref.py, vcmul_ref.py.

Key design decisions (as built)

  • Q1.15 only for v1. Q1.31 and the fused butterfly (vcbfly) are deferred.
  • Round-to-nearest-even everywhere; one rounding step per op (after any add/sub of products), never per product.
  • Saturation clamps to [0x8000, 0x7FFF]; the -1.0*-1.0 = +1.0 case saturates to +0x7FFF (verified in every arithmetic module).
  • Accumulators are a uniform 64-bit per lane, sized so overflow does not occur in practice; only vextract saturates.
  • 16 vector registers, 4 per-lane accumulators (each 8×64b), 2 scalar reduction accumulators (reduction path not in this RTL drop yet).
  • Register file reads are combinational with a write-first bypass; maps to LUT-RAM on the 7020.

CV-X-IF adapter scope and caveats

dsp_cvxif implements the scalar packed ops (sadd.h / ssub.h / smul.h), which map cleanly onto the CV-X-IF GPR-operand model (two 32-bit sources → one 32-bit result, two Q1.15 lanes per word). It:

  • accepts only the custom-0 scalar encodings, rejects everything else;
  • uses coupled issue+register (X_ISSUE_REGISTER_SPLIT = 0, the CV32E40X case);
  • registers operands before computing so there is no combinational path from register.rs to result (a CV-X-IF requirement);
  • produces a result only after commit_valid && !commit_kill; killed instructions produce no result;
  • is single-in-flight (correct for in-order single-issue CV32E40X).

Not yet wired (next work):

  • The vector ops (vld/vst, vsadd.h, vmacc, vcmul, ...) are not driven through this adapter yet. They operate on the internal 128-bit vector register file and need (a) a second custom opcode + vector decode, and (b) the AXI master for vector load/store and gather/scatter. The compute blocks (steps 2, 4, 5) are verified in isolation and ready to connect.
  • The status register (sticky saturation flag) is exposed per-op as sat signals but not yet aggregated into an architectural CSR readable via rdstat/clrstat.
  • No synthesis has been run here. DSP48/LUT/timing numbers on the 7020 must be checked in Vivado. Q1.15 vcmul is ~16 DSP48s of the 220 available.

Simulator notes

Verified with Icarus Verilog 12.0 (iverilog -g2012). Icarus-specific notes, none of which affect synthesis:

  • sorry: constant selects ... and unique/unique0 ... ignored are benign.
  • Functions may not have output args in Icarus — ext_q15 returns a packed value instead.
  • Prefer continuous assign with function calls over always_comb with function calls (an always_comb+automatic-function combination hung Icarus).
  • Vivado (the real synthesis target) accepts all these constructs; consider a Verilator pass for stricter linting.

Build & run (example)

iverilog -g2012 -o s1 q15_alu.sv tb_q15_alu.sv && python3 q15_ref.py > vectors.txt && vvp s1
iverilog -g2012 -o s6 cvxif_pkg.sv q15_alu.sv dsp_decode.sv dsp_cvxif.sv tb_dsp_cvxif.sv && vvp s6
